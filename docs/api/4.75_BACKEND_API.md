# 4.75 Backend and API

## Backend modules

The R2 reference backend is under `backend/` and contains:

```text
backend/src/main/java/com/zerotrust/security/platform/
├── api/
├── domain/
├── governance/
├── observability/
└── store/
```

It also retains the existing SRE incident integration under `com.zerotrust.security.sre`.

## Governance endpoints

The SDK contract defines the following primary API groups:

- `/v1/actions/evaluate`
- `/v1/governance/policies/*`
- `/v1/identity/resolve`
- `/v1/attestation/verify`
- `/v1/capabilities/check`
- `/v1/evidence/*`
- `/v1/approvals/*`
- `/v1/execution/*`
- `/v1/federation/*`
- `/v1/agents/*`
- `/v1/simulations/*`
- `/v1/kubernetes/policies`
- `/v1/observability/*`

The authoritative machine-readable contract is `sdk/contracts/sdk-api.yaml`.

## Event contract

The authoritative event schema is `sdk/contracts/events-asyncapi.yaml`.

Current channels:

- `security.events`
- `governance.decisions`
- `execution.lifecycle`
- `agent.missions`
- `observability.telemetry`

## Error behavior

Clients should preserve the server's typed error information and request correlation identifiers. Retry only operations that are safe to retry; use idempotency keys for mutation workflows that support them.
