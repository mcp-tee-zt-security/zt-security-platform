# Integrated 4.75 API

The only executable backend is `apps/authorization-api`, built by the root Maven project and exposed by Compose at http://localhost:8080. The former independent `backend/` application has been retired.

## Authentication and scope

Use `X-API-Key` (or configured OIDC bearer authentication), UUID `X-Tenant-Id`, and optionally UUID `X-Workspace-Id`. Include the workspace header for workspace-owned policies and lifecycle records. A body tenantId must match the header. SDK writes use existing role checks; execution requires PLATFORM, ADMIN or EXECUTOR, and approval uses the existing APPROVER/ADMIN/PLATFORM checks. Tenant/workspace isolation also applies in PostgreSQL.

## One policy evaluator, two request shapes

The dashboard's structured request remains unchanged:

```json
{"principal":{"id":"payment-agent","type":"AI_AGENT","attributes":{}},"action":{"name":"payment.transfer"},"resource":{"type":"bank_account","id":"ACC-1001","attributes":{}},"context":{"amount":100000,"task_id":"payment-demo-task","tool_id":"33333333-3333-3333-3333-333333333301"}}
```

SDK requests use a registered identity and resource type/id:

```json
{"subject":"payment-agent","action":"payment.transfer","resource":"bank_account/ACC-1001","tenantId":"11111111-1111-1111-1111-111111111111","attributes":{"amount":100000,"task_id":"payment-demo-task","tool_id":"33333333-3333-3333-3333-333333333301"}}
```

Both shapes use ActionEvaluationService: agent boundaries, behavior, policy DSL, continuous risk, approval creation, audit, and SIEM. The SDK subject's type and principal attributes come from the identity table. AI-agent SDK requests require task_id and tool_id. New identities have no implicit allow policy.

Structured responses retain requestId, decision, reason, matchedPolicies, risk, audit and latencyMs. SDK responses additionally expose a durable decision id and traceId for contracts. Decisions are ALLOW, STEP_UP, DENY. SDK facades also recognize legacy REQUIRE_APPROVAL but the integrated server emits STEP_UP.

## Governance lifecycle

| Endpoint | Behavior |
|---|---|
| POST /v1/actions/evaluate | Existing policy/risk pipeline; optional workspace-scoped Idempotency-Key |
| POST /v1/evidence | Persist immutable evidence payload and SHA-256 digest |
| POST /v1/evidence/{id}/verify | Check stored payload digest; does not prove external provenance |
| POST /v1/approvals | Existing approval queue; accept requestId or a persisted SDK decision |
| POST /v1/approvals/{id}/approve | Alias of existing APPROVED decision operation |
| POST /v1/approvals/{id}/decision?status=APPROVED or REJECTED | Existing dashboard approval operation |
| POST /v1/execution/contracts | Bind the stored decision, exact action/resource, evidence IDs, and matching approval |
| GET /v1/execution/contracts/{id} | Retrieve contract state |
| POST /v1/execution/contracts/{id}/execute | Lock contract, check expiry/evidence/approval, re-evaluate through existing pipeline, invoke configured connector |
| POST /v1/execution/{id}/verify | Verify a successful result through the installed connector |

Contracts expire after 15 minutes. Request JSON cannot override a stored decision or attach an approval from another request. Approval assignment and expiry remain authoritative. Contract execution repeats return the stored execution attempt instead of creating another attempt.

A pending STEP_UP approval stops high-level SDK execution. Approve the returned approval using an authorized actor, then explicitly call execute on the returned contract ID; do not run the high-level evaluate-and-execute workflow again with an approval for an older decision.

No external action connector is supplied by default. Authorized execution returns an attempt with status UNSUPPORTED, executed=false and a reason. Verification returns verified=false. An implementation of GovernedActionExecutor must perform a real action, use the contract ID for external idempotency, and verify its result. Local DB locking does not provide distributed exactly-once execution; a connector must handle ambiguous network failures and process crashes.

## Other integrated endpoints

| API | Implementation boundary |
|---|---|
| POST /v1/identity/resolve | Look up the registered identity and active status |
| POST /v1/attestation/verify | HTTP 501, verified=false until a real verifier is installed |
| POST /v1/capabilities/check | HTTP 501, allowed=false until a capability verifier is installed |
| /v1/governance/policies/* | Existing policy lint, blast-radius and as-code implementations |
| POST /v1/agents | Create an identity in the existing identities table |
| POST /v1/agents/{id}/missions | Create a one-hour existing agent task and delegate enabled tools; accept toolIds or objective matching a tool name |
| /v1/runtime/sessions/* | Existing runtime session and authorization endpoints; structured request contracts remain authoritative |
| POST /v1/federation/organizations | Persist organization metadata |
| POST /v1/federation/trust | Persist PENDING_VERIFICATION registration tied to organizationId; trusted=false |
| POST /v1/simulations | Persist simulation specification containing request |
| POST /v1/simulations/{id}/run | Evaluate stored/overridden request with existing policy engine; explicitly POLICY_ONLY, without external execution |
| POST /v1/kubernetes/policies | Persist intent as NOT_APPLIED; applied=false without an apply connector |
| GET /v1/observability/events | Replay integrated lifecycle journal by traceId with tenant/workspace scope; limit 1–500 |
| GET /v1/observability/metrics | Durable integrated lifecycle counts and failed execution rate |
| /v1/operations/sre/incidents/{id}/events | Persist/retrieve tenant/workspace-scoped SRE events; tenantId query, if supplied, must match header |

The integrated lifecycle journal is not a replacement for existing audit and security-event APIs. Lifecycle events also enter the existing security event outbox. Existing data-plane, policy, incident, and response APIs retain their contracts.

## Persistence and deployment

Flyway V3 adds governance_records with tenant/workspace row-level isolation. Decisions, evidence, contracts, execution attempts, verification, federation metadata, simulations, SRE and lifecycle events survive restarts. Existing approval, identity, task and tool tables are reused. Existing V1/V2 migrations are unchanged.

```bash
docker compose -f docker/docker-compose.yml up -d --build authorization-api
```

The implementation has not been built or tested as part of this consolidation, per the requested workflow. SDK contracts are in sdk/contracts/sdk-api.yaml. External event-bus channels in events-asyncapi.yaml describe the integration contract; they do not imply a running broker or connector.
