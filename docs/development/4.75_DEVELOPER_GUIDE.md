# 4.75 Developer Guide

## Repository layout

```text
apps/authorization-api/  Single Spring Boot authorization and SDK execution API
sdk/           multi-language SDKs, contracts, examples and CLI
k8s/           Kubernetes operator and policy resources
docs/          current architecture and operational documentation
scripts/quality/       formatting, lint and source-quality checks
apps/          existing platform applications
services/      existing platform services
infra/         deployment and infrastructure resources
```

## Canonical contracts

Do not create language-specific request models that diverge from the canonical contracts.

- `sdk/contracts/domain-model.json` — domain model
- `sdk/contracts/sdk-api.yaml` — synchronous API contract
- `sdk/contracts/events-asyncapi.yaml` — event contract

## Local backend

The integrated backend is built by the root Maven project and run by Docker Compose on port 8080. Use JDK 17.

```bash
cd apps/authorization-api
mvn test
mvn verify
```

## Formatting policy

New code must be formatted before commit:

- Python: Black + Ruff + isort-compatible import ordering
- TypeScript: Prettier + ESLint
- Java: Google Java Format / Checkstyle configuration in the repository
- Go: gofmt + go vet
- YAML/JSON: Prettier-compatible formatting

The repository intentionally separates formatting cleanup from semantic refactoring. Do not change business behavior merely to satisfy line wrapping.

## Quality checks

### Dashboard workspaces

The sidebar groups pages by workflow. Policy Tests combines Change impact, Historical replay and Live evaluation in tabs. The first two share draft policy text; switching tabs preserves inputs and results, while changing the draft clears outdated comparison results. Live evaluation uses the existing action evaluation API and writes decision/audit records; it does not execute an external action.

Approvals & Execution provides pending approvals, approval history and execution contracts. Detail follows decision → approval → execution → verification and keeps execution success separate from verified outcome. API errors are displayed rather than presented as an empty queue.

Agent Details links to agent-filtered approval/execution records, behavior and audit views where the selected navigation role permits them. Agent audit filtering is limited to the 100 newest tenant records. Policy Studio shows tenant policies, not an inferred assignment to the selected agent.

Copilot opens beside the working page. The page and selected agent seed the recommendation scenario, while analysis remains tenant-wide over the last 120 minutes. Recommendations remain drafts. Close or Escape returns focus to the Copilot button. The Navigation view selector controls menu visibility only; server authorization remains authoritative.

Focused backend verification:

```bash
mvn -pl apps/authorization-api -am -Dtest=WorkflowQueryControllerTest,GovernanceWorkflowQueryTest -Dsurefire.failIfNoSpecifiedTests=false test
```

The `scripts/quality/` directory contains repository source audits. Run `scripts/quality/check.sh` before packaging a milestone.
