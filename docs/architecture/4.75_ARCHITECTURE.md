# 4.75 Architecture — Enterprise Developer Platform

## 1. Purpose

4.75 extends the 4.0 Cyber Defense Intelligence Infrastructure with a developer-facing execution layer. The goal is a single contract surface from identity and governance through execution, verification, events and operational telemetry.

```text
CONTROL
   ↓
DATA → INTELLIGENCE → AGENT
   ↓         ↓          ↓
TRUST → POLICY/GOVERNANCE → EXECUTION
                         ↓
                 VERIFICATION / AUDIT
                         ↓
              EVENT FABRIC / OBSERVABILITY
                         ↓
          SDK / CLI / Kubernetes / Federation
```

## 2. Seven platform planes

| Plane | 4.75 responsibility |
|---|---|
| Control | tenant, organization, policy, approval and capability governance |
| Data | normalized security events, evidence and telemetry |
| Intelligence | context, graph, threat intelligence and decision enrichment |
| Agent | identity-bound, capability-scoped governed agents and missions |
| Execution | execution contracts, connectors, Kubernetes and verification |
| Trust | identity, attestation, provenance, signatures and approval gates |
| Federation | organization, trust-domain and cross-domain exchange contracts |

## 3. Backend execution path

The authorization API provides the integrated governed path:

```text
HTTP request
  → API controller
  → governance service
  → policy/evidence/approval state
  → execution contract
  → execution result
  → verification
  → observability event
```

The existing policy, approval and audit modules are authoritative. SDK lifecycle state is persisted in PostgreSQL; the independent in-memory backend is retired. External execution requires an installed connector.

## 4. Canonical identifiers

Cross-plane correlation uses stable identifiers such as:

- `requestId`
- `traceId`
- `correlationId`
- `causationId`
- `identityId`
- `policyId`
- `evidenceId`
- `approvalId`
- `executionId`
- `agentId`
- `missionId`

## 5. Design rules

1. Policy is evaluated before governed execution.
2. Evidence accompanies important decisions and actions.
3. High-impact actions remain approval-gated.
4. Execution is idempotency-aware.
5. Verification follows execution.
6. Observability is correlated with security decisions rather than treated as application-only logging.
7. Federation uses explicit trust contracts and does not collapse tenant boundaries.
8. 3.x compatibility remains additive during migration.
