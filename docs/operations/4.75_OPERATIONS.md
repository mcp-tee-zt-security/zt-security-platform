# 4.75 Operations

## Operational objectives

Operate the platform around five signals:

1. governance decision health
2. execution safety and verification
3. evidence integrity
4. event-fabric health
5. tenant and federation isolation

## Recommended SLO dimensions

- API availability
- API p95/p99 latency
- policy decision latency
- execution completion rate
- verification completion rate
- event ingestion lag
- event delivery failure/dead-letter rate
- evidence write/verification failure rate
- agent mission failure rate

Use environment-specific targets rather than treating the historical 3.x SLO values as universal 4.75 requirements.

## Failure handling

- Fail closed for authorization and high-impact actions.
- Retry only safe/idempotent operations.
- Preserve correlation and evidence identifiers on failure.
- Prefer isolated failure domains over global shutdown.
- Verify post-action telemetry before marking a governed execution successful.

## Deployment

The single backend is apps/authorization-api; the SDKs and Kubernetes operator remain independently packageable. Deploy the authorization API with Flyway V3 before using integrated SDK lifecycle endpoints. External executors/verifiers remain explicit integrations, and absent connectors must not be reported as successful execution. Deploy contracts and compatibility changes before enabling new execution paths.
