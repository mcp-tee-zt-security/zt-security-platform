# 4.75 Observability

4.75 observability is security-aware telemetry, not only application logging.

## Correlation model

```text
traceId
  └─ correlationId
      ├─ policy decision
      ├─ evidence
      ├─ approval
      ├─ execution contract
      ├─ execution result
      └─ verification
```

`causationId` connects an event to the event or action that caused it.

## Metrics

Track at minimum:

- request count and error rate
- policy decision latency/result
- execution success/failure
- verification success/failure
- evidence operations
- approval latency
- agent mission outcomes
- event throughput/lag
- federation exchange outcomes

## Security telemetry

Security telemetry should preserve the identity, policy, evidence and execution references needed to answer:

> Who initiated this action, under which policy, with which evidence and approval, what executed, and what verified the result?

## Event replay

The event store/reference implementation supports retrieval of correlated security events. Replay is an investigation capability; it must not silently re-execute an action.

## Current implementation boundary

The authorization API persists and replays SDK lifecycle events with tenant/workspace isolation. These events also enter the existing outbox. Production deployments should connect these signals to the organization's metrics, tracing, SIEM/SOC and alerting systems.
