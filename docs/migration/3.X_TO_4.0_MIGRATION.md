# 3.x → 4.x Migration

4.x remains additive to the existing 3.x platform.

## Migration order

1. Apply the V86–V95 4.0 infrastructure migrations.
2. Establish tenant and organization boundaries.
3. Normalize and dual-publish high-value security events.
4. Add provenance and evidence to important decisions.
5. Register governed agents and capabilities.
6. Route new decisions through the 4.0 policy decision plane.
7. Wrap external actions in execution contracts.
8. Enable attestation and trust controls.
9. Use the 4.75 SDK lifecycle integrated into apps/authorization-api for new integrations.
10. Migrate integrations incrementally.

## Compatibility

Existing 3.x APIs and lifecycle components remain available unless an explicit migration removes them. Do not perform a big-bang cutover.

## Safety

Existing approval and four-eyes controls remain authoritative. Adding the SDK or backend does not grant an agent unrestricted production authority.
